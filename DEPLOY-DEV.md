# Развёртывание dev-окружения (dev.r2r.studio)

Пошаговая инструкция. Все команды выполняются **на сервере Hetzner** по SSH,
кроме шага 1 (DNS) и шага 2 (копирование файла с вашего компьютера).

Если какая-то команда выдаёт ошибку — пришлите её вывод целиком, разберём.
Не нужно пытаться «дожать» шаг самостоятельно: лучше остановиться и показать ошибку.

---

## Что мы делаем

Поднимаем вторую копию сайта на том же сервере, на отдельном домене `dev.r2r.studio`.
Прод (`r2r.studio`) при этом не трогается ни в одну секунду: у dev-копии свой контейнер,
свой Traefik-роутер и своё имя. CMS используется та же, что у прода, — сайт из неё только
читает, испортить данные оттуда невозможно.

Dev будет закрыт логином и паролем, чтобы не попал в поисковики и не смущал случайных
посетителей.

---

## Кто за что отвечает: GoDaddy против Hetzner

Это две разные вещи, и путать их — главный источник неразберихи.

**GoDaddy** (или где у вас зарегистрирован домен) — это «телефонная книга». Там написано,
какое имя ведёт на какой адрес: `r2r.studio` → `138.199.217.67`. Больше ничего.
Ни пользователей, ни паролей, ни портов сервера там нет и быть не может.

**Hetzner** — это сам сервер: железо, его IP-адрес, сетевой фильтр, кнопка перезагрузки
и аварийный вход через браузер.

**Имя пользователя и порт SSH** — это настройки операционной системы внутри сервера.
Их не видно ни в GoDaddy, ни, честно говоря, в панели Hetzner. Узнать их можно двумя
способами: войти в сервер через аварийную консоль Hetzner (см. шаг 0) либо спросить
у того, кто этот сервер настраивал.

---

## Шаг 0. Убедиться, что до сервера есть доступ по SSH

**Начинайте отсюда.** Пока этот шаг не пройден, остальные бессмысленны.

### Как читать ошибку подключения

Тексты ошибок означают совершенно разные вещи, и это важно различать:

| Что написано | Что это значит |
|---|---|
| `Connection refused` (порт 22) | До сервера дошли, но SSH там не на 22-м порту. **К имени пользователя отношения не имеет.** |
| `Connection timed out` | Пакеты не доходят — блокирует сетевой фильтр. |
| `Permission denied` | SSH нашли, но не тот пользователь, пароль или ключ. |
| `Host key verification failed` | Сервер сменил отпечаток. Требует отдельного разбора. |

Если вы видите `Connection refused` — искать надо порт, а не пользователя.

### Как найти порт

Сначала быстро прощупаем типичные варианты. Выполните на своём Mac:

```bash
for p in 22 2222 2200 22022 22222 62222; do
  nc -G 3 -z 138.199.217.67 $p 2>/dev/null && echo "порт $p ОТКРЫТ"
done
```

Команда молча проверит шесть портов и напечатает те, что откликнулись.
Если нашёлся открытый порт — дальше во всех командах указывайте его (см. ниже).
Если не откликнулся ни один — переходите к аварийной консоли.

### Аварийная консоль Hetzner

Это вход в сервер через браузер, в обход SSH. Работает, даже когда SSH недоступен.

1. Зайдите на `console.hetzner.cloud`, выберите проект, затем сервер.
2. Убедитесь, что IP сервера — `138.199.217.67`. Если IP другой — значит мы всё это время
   стучались не туда, напишите мне фактический адрес.
3. Нажмите **Console** (иконка терминала в правом верхнем углу). Откроется чёрное окно.
4. Если пароль root неизвестен — в меню сервера есть **Reset root password**, Hetzner
   выдаст новый. Учтите: это меняет пароль на сервере, но ничего не ломает и сайт
   не останавливает.
5. В консоли выполните две команды и пришлите мне их вывод:

```bash
ss -tlnp | grep -i ssh
getent passwd | grep -E 'bash|sh$' | cut -d: -f1
```

Первая покажет, на каком порту слушает SSH. Вторая — какие пользователи есть в системе.

> Если в панели Hetzner нет кнопки Console, значит это не Cloud, а выделенный сервер
> (Hetzner Robot). Там вместо консоли — аварийная система Rescue. Напишите мне, что
> увидели, подскажу по факту.

### Когда порт известен

Во всех дальнейших командах его надо указывать явно. Обратите внимание: у `ssh` ключ
маленький `-p`, а у `scp` — **большой `-P`**. Это классическая ловушка.

```bash
ssh -p 2222 root@138.199.217.67
scp -P 2222 ~/Downloads/r2r-dev.bundle root@138.199.217.67:/opt/
```

### Если доступа так и нет

Вполне возможно, что SSH на этом сервере открыт только с определённых адресов или
только по ключу, которого у вас нет, — сервер настраивал подрядчик, и хозяйничает там
он. Это не тупик, но развилка: либо мы запрашиваем доступ у подрядчика, либо разворачиваем
dev на отдельном сервере, который целиком ваш. Напишите мне, что выяснится, — обсудим.

## Шаг 1. DNS-запись

**Похоже, этот шаг уже сделан.** Я проверил: `dev.r2r.studio` уже отвечает адресом
`138.199.217.67` — нужная запись в DNS кем-то создана. Проверить самому:

```bash
dig +short dev.r2r.studio
```

Если вывелось `138.199.217.67` — идите дальше, ничего делать не нужно.

Если вывелось пусто, то в панели GoDaddy надо добавить запись:

```
тип: A
имя: dev
значение: 138.199.217.67
```

Если домен проксируется через Cloudflare, для этой записи поставьте режим
**DNS only** (серая тучка), иначе Let's Encrypt не сможет выдать сертификат.

## Шаг 2. Загрузить код на сервер

**Зачем этот шаг.** Код сайта сейчас лежит у меня и у вас в чате. Серверу его надо
как-то отдать. Мы кладём на сервер один файл с проектом и распаковываем его там.

> **Если мы уже настроили GitHub — этот шаг не нужен.** Тогда код попадает на сервер
> автоматически, и вручную ничего копировать не придётся. См. врезку в конце шага.

Ниже — по одному действию за раз. Команды можно копировать целиком, вместе со всеми
знаками. Строки, начинающиеся с `#`, — это пояснения, их копировать не нужно
(но если скопируются — ничего не сломается, терминал их проигнорирует).

### 2.1. Сохранить файл проекта

В чате я прислал файл `r2r-dev.bundle`. Скачайте его — он попадёт в папку «Загрузки»
(`~/Downloads`). Больше с ним ничего делать не надо: ни распаковывать, ни открывать.

### 2.2. Открыть терминал на своём Mac

Нажмите `Cmd + Пробел`, наберите `Терминал` (или `Terminal`) и нажмите Enter.
Откроется окно с текстовой строкой — это и есть терминал. Дальше все команды
набираются (вставляются) туда, каждая — с нажатием Enter в конце.

### 2.3. Скопировать файл на сервер

```bash
scp ~/Downloads/r2r-dev.bundle root@138.199.217.67:/opt/
```

Здесь `root` — имя пользователя, а `138.199.217.67` — адрес сервера. Оба значения вы
выяснили на шаге 0; подставьте свои. **Если SSH оказался не на 22-м порту, команда
выглядит так** (у `scp` порт задаётся большой буквой `-P`):

```bash
scp -P 2222 ~/Downloads/r2r-dev.bundle root@138.199.217.67:/opt/
```

Что произойдёт: терминал спросит пароль от сервера (или молча пропустит, если у вас
настроен вход по ключу). При вводе пароля **символы не отображаются** — это нормально,
не пугайтесь, что «ничего не печатается». Наберите и нажмите Enter.

Дальше побежит строка прогресса. Файл весит около 12 МБ, так что займёт несколько секунд.
Признак успеха — строка вида:

```
r2r-dev.bundle              100%   12MB   4.2MB/s   00:02
```

Если вместо этого ошибка — сверьтесь с таблицей в шаге 0: `Permission denied` означает
проблему с пользователем или паролём, `Connection refused` — что порт указан не тот.

### 2.4. Зайти на сервер

```bash
ssh root@138.199.217.67
```

Если SSH не на 22-м порту — добавьте `-p` с номером порта (у `ssh`, в отличие от `scp`,
буква маленькая):

```bash
ssh -p 2222 root@138.199.217.67
```

Снова тот же пользователь и тот же пароль. После входа приглашение в терминале
изменится — вместо имени вашего компьютера появится имя сервера. Это значит, что
теперь все команды выполняются **на сервере**, а не у вас.

Если при первом входе спросит `Are you sure you want to continue connecting (yes/no)?` —
наберите `yes` и Enter. Это обычный вопрос при первом подключении.

### 2.5. Распаковать проект

Теперь, находясь на сервере, выполните по очереди:

```bash
cd /opt
git clone r2r-dev.bundle r2r-front-dev
cd r2r-front-dev
git log --oneline
```

Последняя команда должна вывести список из 8 строк — это история наших правок.
Верхняя строка — про Dockerfile и sharp, ниже — про звёздочку, соцсети, логотип.
Если список вывелся — шаг пройден, переходите к шагу 3.

Если `git clone` пишет `command not found`, значит на сервере нет git. Тогда выполните
`apt update && apt install -y git` и повторите.

Чтобы вернуться со сервера к себе на компьютер, есть команда `exit`. Но сейчас
выходить не надо — следующие шаги тоже делаются на сервере.

---

> **Как это будет выглядеть после настройки GitHub.** Шаги 2.1–2.3 исчезнут полностью:
> код будет лежать в репозитории, и на сервере достаточно будет одной команды
> `git clone <адрес репозитория> /opt/r2r-front-dev`. А выкладку новых правок вообще
> будет делать автоматика — без терминала с вашей стороны.

## Шаг 3. Придумать логин и пароль для dev

Сгенерируем хеш пароля. Замените `mypassword` на свой пароль:

```bash
docker run --rm httpd:2.4-alpine htpasswd -nb dev 'mypassword'
```

Команда выведет строку вида `dev:$apr1$abc...$xyz...`

Теперь **удвойте в ней каждый знак `$`** — так требует docker compose.
Проще всего сделать это автоматически:

```bash
cd /opt/r2r-front-dev
HASH=$(docker run --rm httpd:2.4-alpine htpasswd -nb dev 'mypassword')
echo "DEV_BASIC_AUTH=$(echo "$HASH" | sed -e 's/\$/\$\$/g')" > .env
cat .env
```

Файл `.env` в git не попадёт — он в списке игнорируемых.

## Шаг 4. Проверить, что сеть Traefik называется `web`

```bash
docker network ls | grep web
```

Если в выводе есть строка с именем `web` — всё в порядке, идём дальше.
Если такой сети нет, пришлите мне полный вывод `docker network ls`
и `docker ps --format '{{.Names}}'` — поправлю конфиг под фактические имена.

## Шаг 5. Собрать и запустить

```bash
cd /opt/r2r-front-dev
docker compose -f docker-compose.dev.yml up -d --build
```

Первая сборка займёт минуты три-четыре: скачиваются зависимости и собирается проект.

Посмотреть, что получилось:

```bash
docker compose -f docker-compose.dev.yml ps
docker compose -f docker-compose.dev.yml logs --tail=50
```

В логах должна быть строка вида `✓ Ready in ...`.

---

## Шаг 6. Проверить

Сначала изнутри сервера, минуя Traefik и авторизацию:

```bash
docker exec r2r-front-dev wget -qO- http://127.0.0.1:3000/api/health
```

Ожидаемый ответ: `{"status":"Healthy","timestamp":"..."}`

Затем откройте в браузере **https://dev.r2r.studio** — браузер спросит логин и пароль
из шага 3. Первое открытие может занять до минуты: Traefik в этот момент получает
сертификат.

## Если что-то пошло не так

Собрать диагностику одной командой и прислать мне вывод:

```bash
cd /opt/r2r-front-dev
echo "--- ps ---";        docker compose -f docker-compose.dev.yml ps
echo "--- logs ---";      docker compose -f docker-compose.dev.yml logs --tail=80
echo "--- traefik ---";   docker logs $(docker ps --format '{{.Names}}' | grep -i traefik | head -1) --tail=50
echo "--- dns ---";       getent hosts dev.r2r.studio
```

## Как выкладывать следующие правки

После того как окружение поднято, обновление сводится к трём командам:

```bash
cd /opt/r2r-front-dev
git pull                                                    # либо новый bundle, см. ниже
docker compose -f docker-compose.dev.yml up -d --build
```

Пока нет своего git-сервера, вместо `git pull` будет так: я присылаю новый bundle,
вы его копируете на сервер и делаете

```bash
git pull /opt/r2r-dev.bundle master
```

Когда поднимем Gitea (это отдельная задача), останется обычный `git pull`.

---

## Как убрать dev-окружение

```bash
cd /opt/r2r-front-dev
docker compose -f docker-compose.dev.yml down
```

Прод это никак не затронет.
