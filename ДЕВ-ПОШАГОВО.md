## Часть 1. То, что делаете вы у себя (5 минут)

Нужна ровно одна вещь: место в интернете, куда я положу код и откуда сервер его возьмёт.
Своими руками я до вашего сервера не достаю, а до GitHub — достаю. Поэтому GitHub.

### 1.1. Создать репозиторий

Зайдите на `github.com`, нажмите **New repository**.

- Имя: `r2r-front`
- Видимость: **Private**
- Галочки «Add README», «Add .gitignore», «Add license» — **не ставить**, репозиторий
  должен быть пустым

Нажмите **Create repository**. Скопируйте адрес из адресной строки, он выглядит как
`https://github.com/ваш-логин/r2r-front`, и пришлите мне.

### 1.2. Создать токен доступа

Токен — это как одноразовый ключ, которым я смогу положить код в этот репозиторий.

1. Откройте `github.com/settings/personal-access-tokens/new`
   (это же меню: Settings → Developer settings → Personal access tokens → Fine-grained)
2. **Token name:** `claude-r2r`
3. **Expiration:** 7 days
4. **Repository access:** Only select repositories → выберите `r2r-front`
5. **Permissions** → Repository permissions, выставьте два пункта:
   - `Contents` → **Read and write**
   - `Workflows` → **Read and write**
6. **Generate token**, скопируйте и пришлите мне

Токен даёт доступ только к этому одному пустому репозиторию, живёт неделю
и отзывается одной кнопкой в том же меню. Если он вам разонравится — отзовите,
я просто не смогу пушить, ничего не сломается.

### 1.3. Дальше моя часть

Я заливаю восемь коммитов в репозиторий и говорю вам, что готово. Минута.

## Часть 2. То, что делаете вы на сервере (10 минут)

Всё это — в веб-консоли Hetzner, под пользователем root.

Команды короткие специально: в консоли Hetzner вставка текста работает через
боковую панель с иконкой буфера обмена, а если она капризничает — их реально набрать
руками.

### 2.1. Проверить, что сеть Traefik называется `web`

```
docker network ls
```

В списке должна быть строка `web`. Она там есть — прод в ней и живёт, — но лучше
убедиться глазами. Если строки `web` нет, остановитесь и напишите мне.

### 2.2. Забрать код

```
cd /opt
git clone АДРЕС_РЕПОЗИТОРИЯ r2r-dev
cd r2r-dev
```

Вместо `АДРЕС_РЕПОЗИТОРИЯ` — то, что вы скопировали в шаге 1.1.
Git спросит логин и пароль: **логин** — ваш логин на GitHub, **вместо пароля**
вставьте тот же токен из шага 1.2.

Если `git` ответит `command not found`:

```
apt update && apt install -y git
```

и повторите.

### 2.3. Убедиться, что код на месте

```
ls
```

Должны увидеть среди прочего `Dockerfile`, `docker-compose.dev.yml`, `package.json`.

### 2.4. Задать пароль для dev-сайта

Пароль я сгенерировал заранее, вместе с зашифрованным видом, — чтобы вам не
возиться с генерацией и экранированием символов. Выполните эту строку целиком:

```
echo 'DEV_BASIC_AUTH=dev:$$apr1$$fHf4xO9.$$PxPrJC4yWAB4ob2IerU83.' > .env
```

Кавычки обязательны, иначе знаки `$` съест сама командная строка.

Проверить, что записалось верно:

```
cat .env
```

Строка должна выглядеть точно как выше, с удвоенными `$`.

**Запомните, что вводить в браузере:**

- логин: `dev`
- пароль: `0meu-m4f8-uto1`

### 2.5. Собрать и запустить

```
docker compose -f docker-compose.dev.yml up -d --build
```

Это самый долгий шаг: три-четыре минуты. Побегут строки про скачивание Node,
установку зависимостей и сборку. Это нормально.

Признак успеха в конце — строка вида `Container r2r-front-dev  Started`.

### 2.6. Проверить

```
docker compose -f docker-compose.dev.yml ps
```

Статус должен быть `Up`, а рядом — `(healthy)` через полминуты.

Затем проверка изнутри, минуя Traefik:

```
docker exec r2r-front-dev wget -qO- http://127.0.0.1:3000/api/health
```

Ожидаемый ответ: `{"status":"Healthy","timestamp":"..."}`

### 2.7. Открыть в браузере

**https://dev.r2r.studio** — браузер спросит логин `dev` и пароль `0meu-m4f8-uto1`.

Первое открытие может занять до минуты: Traefik в этот момент получает сертификат.
Если увидите предупреждение о сертификате — подождите минуту и обновите страницу.

Напишите мне, когда откроется, — я проверю английскую версию снаружи и через браузер,
как мы и планировали.

## Если что-то пошло не так

Соберите диагностику и пришлите мне вывод:

```
cd /opt/r2r-dev
docker compose -f docker-compose.dev.yml ps
docker compose -f docker-compose.dev.yml logs --tail=60
docker logs traefik --tail=30
```

**Прод при этом в безопасности.** Dev — отдельный контейнер, с отдельным именем,
отдельным доменом и отдельными именами маршрутов в Traefik. Ни одна из команд выше
прод не касается. Если dev не заведётся, сайт продолжит работать как ни в чём не бывало.

## Как выкладывать следующие правки

После того как окружение поднято, обновление — две команды:

```
cd /opt/r2r-dev
git pull
docker compose -f docker-compose.dev.yml up -d --build
```

А когда настроим автоматику, и этого не понадобится: я пушу код, GitHub сам заходит
на сервер и обновляет dev.
