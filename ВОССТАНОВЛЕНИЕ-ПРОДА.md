# Аварийное восстановление прода r2r.studio

## Что произошло на самом деле

В консоли Hetzner было нажато **Ctrl + Alt + Delete**. Это не удаление, а перезагрузка
сервера. **Ничего не удалено.** Ни образов, ни контейнеров, ни данных.

Сайт лёг по другой причине, и она давно ждала своего часа: в `docker-compose.yml`
у сервисов `blue-web` и `green-web` **не задана политика перезапуска**. Секция
`deploy.restart_policy`, которая там есть, работает только в режиме Docker Swarm —
обычный `docker compose` её игнорирует. Поэтому после любой перезагрузки сервера
контейнеры сайта остаются лежать, пока их не поднимут руками.

Traefik и Strapi, судя по тому что они отвечают, политику перезапуска имеют —
поэтому вернулись сами, а сайт нет. Traefik без контейнеров сайта не знает
маршрута для домена и отдаёт `404 page not found`.

**Восстановление: просто запустить контейнер обратно.** Смотрите вариант А ниже,
это секунды. Варианты Б и В в этой ситуации не нужны — они на случай реального удаления.

Отдельно, потом: отсутствие политики перезапуска надо починить, иначе история
повторится при следующей перезагрузке, в том числе незапланированной.

## Что видно снаружи

Проверено снаружи:

- `https://r2r.studio/` → **404 page not found**. Это ответ Traefik, когда для домена
  не осталось ни одного маршрута. То есть контейнеры сайта удалены вместе со своими
  метками, и Traefik больше не знает, куда отправлять запросы.
- `https://cms.r2r.studio/admin` → отвечает нормально. **Strapi жив, контент цел.**
  Это самое важное: содержимое сайта не потеряно, потеряна только «обёртка».
- DNS в порядке: `r2r.studio` по-прежнему указывает на `138.199.217.67`.

Исходный код сайта тоже цел — он лежит в git в восьми коммитах, включая самый первый,
`098f0d5`, где зафиксировано состояние ровно как на проде до всех наших правок.

Вывод: ситуация полностью обратима. Ничего безвозвратно не потеряно.

## СНАЧАЛА ПРОЧТИТЕ: чего нельзя делать

Пока не выяснили состояние сервера, **не выполняйте** следующие команды, даже если
где-то посоветуют:

- `docker system prune`, `docker image prune`, `docker volume prune` — они удалят
  образ, из которого можно поднять сайт за минуту, и восстановление станет намного дольше
- `docker volume rm` — убьёт данные, если под руку попадётся том Strapi
- переустановку или пересоздание сервера в панели Hetzner
- перезагрузку сервера — если контейнеры ещё живы, но остановлены, перезагрузка
  может усложнить картину

Ничего срочно чистить не нужно. Место на диске подождёт.

## Шаг 1. Собрать состояние сервера

Зайдите на сервер (через SSH или аварийную консоль Hetzner — см. `DEPLOY-DEV.md`, шаг 0)
и выполните этот блок целиком. Он ничего не меняет, только смотрит.

```bash
echo "=== 1. работающие контейнеры ==="
docker ps --format '{{.Names}}\t{{.Image}}\t{{.Status}}'

echo "=== 2. ВСЕ контейнеры, включая остановленные ==="
docker ps -a --format '{{.Names}}\t{{.Image}}\t{{.Status}}'

echo "=== 3. образы на сервере ==="
docker images --format '{{.Repository}}:{{.Tag}}\t{{.Size}}\t{{.CreatedSince}}'

echo "=== 4. тома ==="
docker volume ls

echo "=== 5. где лежал проект ==="
ls -la /opt 2>/dev/null
find / -maxdepth 4 -name 'docker-compose*.y*ml' -not -path '*/node_modules/*' 2>/dev/null

echo "=== 6. жив ли Traefik ==="
docker ps --format '{{.Names}}' | grep -i traefik
```

**Пришлите мне весь вывод.** По нему я скажу точно, каким из вариантов ниже идти.

## Шаг 2. Выбрать вариант восстановления

Варианты идут от самого быстрого к самому долгому. Какой подойдёт — определяется
выводом из шага 1.

### Вариант А. Контейнеры целы, просто остановлены — ЭТО НАШ СЛУЧАЙ

Признак: в пункте 2 есть `blue-web` или `green-web` со статусом `Exited`.

Восстановление занимает секунды. Сначала посмотрите точное имя:

```bash
docker ps -a
```

Имя контейнера может быть с приставкой — в исходном `docker-compose.yml` строка
`container_name` закомментирована, поэтому Docker подставляет имя папки проекта:
получается что-то вроде `r2r-blue-web-1`. Дальше запускаем по фактическому имени:

```bash
docker start r2r-blue-web-1
```

Если контейнеров `blue-web` и `green-web` два — достаточно поднять один, любой.

Альтернатива, если нашли папку проекта из пункта 5 — поднять всё сразу:

```bash
cd <папка с docker-compose.yml>
docker compose up -d
```

Проверить: `curl -s -o /dev/null -w '%{http_code}\n' https://r2r.studio/` → ждём `200`.
Сертификат перевыпускать не придётся, он лежит у Traefik и никуда не девался.

### Вариант Б. Контейнеров нет, но образ на месте

Признак: в пункте 2 контейнеров сайта нет, но в пункте 3 есть образ — скорее всего
что-то с `harbor.infra.s2app.ru` в названии, или с `r2r`, или с `stackdemo`.

```bash
# подставьте точное имя образа из пункта 3
export R2R_IMAGE=harbor.infra.s2app.ru/...:s2-...

cd /opt/r2r-restore   # папку создадим на следующем шаге, если её нет
docker compose -f docker-compose.prod-restore.yml up -d
```

Файл `docker-compose.prod-restore.yml` лежит в нашем репозитории. Метки Traefik,
порт 5000, пользователь и том в нём — ровно как в исходной конфигурации.

### Вариант В. Не осталось ни контейнеров, ни образа

Тогда собираем сайт из исходников прямо на сервере, без реестра подрядчика:

```bash
cd /opt/r2r-restore
git checkout 098f0d5          # ВАЖНО: исходная русская версия, та что была на проде
docker compose -f docker-compose.prod-rebuild.yml up -d --build
```

Сборка займёт минуты три-четыре. Сайт при этом поднимется точно в том виде,
в каком он работал до удаления.

> **Почему именно `098f0d5`, а не `master`.** В `master` лежит английская версия
> с новым логотипом и Facebook с Discord. Она готова, но на прод не согласована
> и в браузере вами не проверена. Аварийное восстановление — не место для
> первого показа новой версии. Сначала возвращаем как было, потом спокойно
> выкладываем новое.

## Шаг 3. Проверить, что вернулось

```bash
curl -s -o /dev/null -w 'главная: %{http_code}\n'  https://r2r.studio/
curl -s -o /dev/null -w 'health:  %{http_code}\n'  https://r2r.studio/api/health
curl -s -o /dev/null -w 'policy:  %{http_code}\n'  https://r2r.studio/privacy-policy
```

Все три должны ответить `200`. Если `/api/health` отвечает 200 — значит сам сайт жив
и Traefik его нашёл; это главный признак.

Скажите мне, когда получите эти три числа, — я перепроверю сайт снаружи и посмотрю,
всё ли на месте визуально.

## Что сделать после, чтобы это не повторилось

Не сейчас, а когда всё поднимется:

1. **Починить политику перезапуска — это главное.** Добавить `restart: unless-stopped`
   сервисам `blue-web` и `green-web` в `docker-compose.yml`. Сейчас любая перезагрузка
   сервера — плановая, аварийная, после обновления ядра — гасит сайт до тех пор,
   пока кто-то не заметит и не поднимет руками. Правка на одну строку, я её подготовлю.
2. Снимок диска сервера в панели Hetzner — делается в два клика и откатывается так же.
3. Резервная копия базы Strapi по расписанию. Сейчас, судя по всему, её нет,
   и это куда более серьёзный риск, чем остановленные контейнеры: контент
   восстанавливать будет нечем.
4. Мониторинг доступности домена с оповещением. Сегодня о том, что сайт лежит,
   мы узнали случайно.
5. Выкладка через автоматику, а не руками. Тогда и возврат предыдущей версии —
   одна кнопка.
